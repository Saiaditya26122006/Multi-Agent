## What changed, by area

### Canonical registry (Alex issue #2 — node IDs)
- `ceo_data/bp_architecture.json` rebuilt from the Google Sheet (gid=0): **840
  nodes, 12 domains incl. BP.12**. 64 node-ID collisions in the sheet were
  de-duplicated by completeness (kept the fully-populated node, dropped the stub).
- `business_plan_sections` synced to 840 rows; the 746 falsely-`approved` nodes
  reset (10 evidence-bearing → `in_progress`, rest → `not_started`).
- `memory/supabase_client.set_section_status()` is now the **only** sanctioned
  status writer — `approved` requires `controller_approved=True` (AI can't self-approve).
- 23 empty sheet nodes filled with meaningful purpose/required_output.
- Scripts: `build_canonical_architecture.py`, `reset_bp_section_status.py`,
  `reembed_architecture.py`, `fill_empty_nodes.py`.
- Reports: `evaluation/ARCHITECTURE_SYNC_REPORT.md`, `SHEET_NODE_ID_COLLISIONS.md`.

### Governance — contradictions & BP.12 (Alex concerns 1 & 4)
- `web/handlers/llm_helper.judge_contradiction()` — LLM judges whether two facts
  are incompatible (replaces the dead circular precondition + Titan threshold trap).
- `web/handlers/feed_handler._run_post_store_hooks` — retrieves candidates at the
  real Titan threshold (0.4) and files genuine contradictions to `bp12_register`
  (no auto-resolution). Assumption-conflict block fixed the same way.
- `scripts/populate_bp12.py` scanned existing same-node fact pairs → **23 BP.12
  items** (all `open`). Re-runnable (idempotent).

### Classifier accuracy
- `evaluation/gold_standard.json` — 40 facts, **Alex-confirmed** answer key.
- `scripts/measure_classifier.py` → **38% exact / 75% domain** (was measured as
  "22%" against a broken pilot gold that filed everything to BP.1.1.x).
- Two fixes in `feed_handler.classify_and_match_node`: rescue over-eager `none_fit`
  on a strong embedding match; widen candidate recall (threshold 0.3→0.2).
- `scripts/reclassify_facts.py` — 366 unclassified facts run through the classifier
  and stored as **pending_review** (never auto-filed): 294 proposed, 72 no-fit.
  Promote `metadata.proposed_node_id` → authoritative after human review.

### Claims & supersession (Alex issues #3, #5)
- `services/claims.py` + `add_claims.sql` — first-class claims per node; evidence
  links point via `claim_id`. `backfill_claims_from_evidence_links()` populates it
  (after the RLS fix above).
- `feed_handler._flag_supersession_candidates()` — update-language detection flags
  the prior fact as a supersession *candidate* for controller review;
  `confirm_supersession()` applies it. Explicit CEO corrections still auto-supersede
  via `conversation_store` (mechanism verified working).

### Bug fixes
- `log_event` never drops events on non-UUID/absent session (FK-safe fallback).
- Message dedup fixed — the L0 call used a wrong kwarg, so nothing was ever logged
  and dedup never fired. Now channel-agnostic (bigint-mapped ids).
- L1 tests: isolation fix (the 3-question cap works as designed; failure was
  accumulated live-DB state).
- `classify_fact_to_domain` guards empty LLM responses.
- Stale `pipeline_runs` auto-close on startup + `close_stale_runs()`; fixed
  `_fail_pipeline` writing a non-existent `error` column (→ `failure_reason`).

### Web-only
- Web Interface removed as a channel: not run (`main()` is web-only), not required
  (not in `verify_system`), outbound already web (`send_reply`), CEO-facing text
  cleaned. `ingestion_pipeline` Path B guarded behind `--force-legacy`.
- Legacy column names (`Web Interface_chat_id`, `Web Interface_message_id`) kept as generic
  identifiers — renaming is a risky DB migration with no functional benefit.

  accuracy with threshold tweaks (overfitting). To go further: expand the gold set
  to ~150 facts, then address the two structural issues — BP.1.8 over-attracts
  ("Technical/vendor architecture" pulls unrelated facts) and Stage-1 domain
  classification occasionally misses (e.g. WTP facts not routed to BP.9).
- **BP.12's 23 items need Alex's adjudication** — they are candidates, by design.
- **The 294 pending-review classifications** need promotion to authoritative
  `node_id` after review.
- **E13 (two overlapping systems)** — linkage columns + decision doc delivered; the
  full data backfill/dedup of assumption/decision representations is a follow-up.
- **E15 (RLS)** — policies written but blocked on role separation (per-actor
  Supabase credentials); the app shares one anon key today.
