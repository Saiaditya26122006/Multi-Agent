### Base class changes made during migration

- `start()` takes `register_as` — the bus key must be the **roster key**
  (`environment_research`), not the name derived from `AGENT_NAME`
  (`EnvironmentResearch` → `environmentresearch`), which would silently dead-letter
  every request. `PipelineOrchestrator` passes the roster key.
- `_augment_parsed(parsed, input_package)` hook — injects computed fields into the
  parsed output before schema validation. Used by `financial_modelling` to attach
  SimPy results (`probability_distribution`, `primary_risk_factor`,
  `simpy_runs_completed`, `financial_skills_applied`).

### Orchestrator fixes found during migration

Fixing `pipeline_orchestrator.py`'s import of the non-existent
`database.supabase_client` (the class lives in `memory.supabase_client`) made
`tests/test_build_handler.py` collectable again — its collection error had been
aborting the whole pytest session. That exposed two genuine production bugs:

- **`start_build` could never start a pipeline.** It called `asyncio.create_task()`,
  but `web/server.py` dispatches the sync handler through `asyncio.to_thread()`, so
  there is no running loop on that thread and it raised `RuntimeError`. The error was
  swallowed and surfaced to Alex as `status: error`. Now routed through
  `_schedule_pipeline()`, which uses the running loop when there is one and otherwise
  runs the pipeline on its own loop in a daemon thread.
- **Every `pipeline_runs` insert was rejected.** `_create_pipeline_run` wrote the
  orchestrator's `scope` ("all" / a section number) into `run_mode`, but the
  `pipeline_runs_run_mode_check` constraint only accepts `"full_pipeline"` (verified
  against the live table — 29 other candidates were rejected). The requested scope
  belongs in the `sections_requested` array column. Note the `except` still returns a
  synthetic `run_{timestamp}` id on failure, so a broken insert degrades silently —
  worth revisiting.

`pipeline_runs` is not defined in `database/migrations/`, so the constraint can only
be inspected against the live database.

### Agent-specific notes

- Agents whose output is council-gated (`summary_agent`, `swot_synthesizer`,
  `marketing_strategy`, `financial_modelling`) override `_send_inform()` to address
  `council_agent` rather than `mother_agent`.
- Cross-agent `propose` checks that previously lived in `_check_contradictions()` now
  use the `_post_process()` hook (`swot_synthesizer`, `financial_modelling`).
- `marketing_strategy` enforces the LTV:CAC magic-ratio guardrail inside
  `_send_inform()`, escalating instead of informing when the ratio is under 3.0
  without justification.
- `schemas/inputs/summary_agent.py`: `pipeline_run_id` defaulted to `""` — the base
  class only passes `task_id`/`session_id` into `INPUT_SCHEMA`.

## Migration Template

Every standalone agent follows this pattern. Here's the step-by-step:

### 1. Read the existing file

Note these key elements:
- `SYSTEM_PROMPT` (keep verbatim)
- Section number (in `_escalate` call: `"section": "X"`)
- Gap key (in `_escalate` call: `"gap_key": "..."`)
- Model (in `__init__`: `CLAUDE_SONNET_MODEL` or `CLAUDE_HAIKU_MODEL`)
- Input/output schemas imported at top
- The logic in `handle_request` that builds the Input kwargs
- The `input_data` dict passed to `intelligence.reason_and_produce`
- The fallback dict in `_parse_llm_response` (after "constructing fallback")

### 3. Remove these from the original

- `import sys; sys.path.insert(...)`
- `from spade.agent import Agent`
- `from spade.behaviour import CyclicBehaviour, OneShotBehaviour`
- `from spade.message import Message`
- `from memory.redis_client import RedisClient`
- `from agents.phase2.llm_utils import signal_ready` import
- `ListenBehaviour` class
- `__init__(self, jid, password)`
- `setup(self)`
- `_send_msg(self, msg)`
- `_escalate(...)`
- `_send_inform(...)`
- `_call_llm(...)`
- `handle_propose(...)`
- `async def main()` and `if __name__ == "__main__"`

### 4. Keep these helpers (if they exist)

- Module-level functions like `_get_live_market_data()`
- Module-level constants like `SEARCH_QUERIES`
- Any agent-specific domain logic

### 5. Special cases

#### Financial Modelling Agent
- Has `self.simpy_runs` — ignore it, not used in BaseChildAgent
- Uses `simulation.financial_sim.run_simulation()` — keep the import and call it in `_parse_llm_response` or `_build_ie_input_data`

#### Summary Agent
- `executive_summary` field has `min_length=200` constraint
- The fallback text MUST be at least 200 characters

#### Marketing Strategy Agent
- Likely the longest (621 lines) — same pattern, just more complex prompt
- May have multiple helper functions — keep them
